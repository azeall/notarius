# План: «Папка» на site-warm

## Кратко

Главная перестаёт быть витриной из двенадцати блоков и становится приёмом. Человек
называет дело на первом экране, и дальше страница ведёт его по четырём шагам, складывая
собранное в «папку» — закреплённую полосу внизу. В конце папка печатается памяткой.
Всё остальное на сайте — внутренние страницы, маршруты, форма записи, разметка — не
трогается.

## Технический контекст

- Next 14 app router, Tailwind 3, без новых зависимостей.
- Состояние приёма (дело, отметки, время) живёт в **одном** клиентском компоненте
  `components/Intake.tsx`. Никаких контекстов и внешних хранилищ: всё, что связано
  общим состоянием, стоит рядом в разметке.
- Данные дел — новый `lib/cases.ts`, собранный из уже существующих перечней. Второго
  списка на те же услуги не появляется: `BringChecklist` переводится на `lib/cases.ts`
  или заменяется частью `Intake`.
- Печать — `@media print` в `globals.css` плюс скрытый блок памятки в разметке.

## Проверка по конституции

| Принцип | Как выполняется |
|---|---|
| I. Главная ведёт | Первый экран = выбор дела; четыре шага; папка внизу |
| II. Пустота не воздух | Зигзаг → сетка, провалы срезаны, цель ≤ 6 000 px |
| III. Всё сразу | Пять шагов сделки без карусели |
| IV. Тёплый и читаемый | Плоскости разведены по светлоте, контраст проверен |
| V. Вымышленное названо | Пометка в блоке отзывов |
| VI. Не ломать | Внутренние страницы и тесты не трогаем, `npm test` зелёный |

## Устройство

```
lib/cases.ts             один перечень дел: документы, срок, явка, цена, обязанности
components/Intake.tsx    приём: выбор дела, карточка, чек-лист, время, папка, памятка
components/DealSteps.tsx пять шагов сделки сразу (замена DealTimeline)
components/ServicesTiles.tsx  сетка услуг (замена зигзага в page.tsx)
app/page.tsx             новая сборка главной
app/globals.css          стили печати + поднятые поверхности
components/CookieNotice.tsx  компактная карточка вместо полосы
```

Удаляются из главной: карусель `DealTimeline`, зигзаг услуг, отдельный `BringChecklist`
(его содержание переезжает в `Intake`). Сами файлы остаются, если на них ссылаются
внутренние страницы, — проверяется поиском по репозиторию.

## Порядок блоков новой главной

1. **Приём** — первый экран: контора, статус, вопрос «с чем пришли» и шесть дел.
2. **Ваше дело** — карточка выбранного: срок, явка, цена «от», что берёт на себя нотариус.
3. **Что взять с собой** — чек-лист с отметками, счётчик, кнопка «Памятка».
4. **Когда прийти** — форма записи (`BookingInline`), время попадает в папку.
5. **Куда прийти** — карта и часы.
6. **Как проходит сделка** — пять шагов сразу.
7. **Услуги** — сетка, ссылки на внутренние страницы.
8. **О нотариусе и полномочия** — как есть, компактнее.
9. **Отзывы** — с пометкой «вымышлены».
10. **Вопросы** — поиск как есть.

Папка (`sticky bottom`) видна начиная со второго блока.

## Учёт сложности

| Решение | Зачем | Что отвергнуто |
|---|---|---|
| Одно клиентское дерево `Intake` | состояние не расползается | React Context на всю страницу |
| `lib/cases.ts` как единственный перечень | два списка на одни услуги расходятся при первой правке | оставить данные внутри `BringChecklist` |
| Печать через `@media print` | нативно, без библиотек и без сервера | генерация PDF |
| Пять шагов без карусели | пять фраз читаются быстрее, чем пять нажатий | оставить «Дальше» ради интерактивности |
