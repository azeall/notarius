# Сайт нотариуса — шаблон

Готовый сайт нотариальной конторы: услуги, цены, подготовка к визиту, блог,
контакты, разметка для поисковиков. Заводится под нового нотариуса
заполнением файлов в `lib/` — вёрстку трогать не нужно.

## Что заполнить

Порядок — от обязательного к необязательному. Всё лежит в `lib/`.

### 1. `lib/data.ts` — сведения о конторе

Главный файл. Отсюда имя, адрес и телефон расходятся по всем страницам,
в подвал, в разметку для поисковиков и в карту.

| Поле | Что вписать | Если не заполнить |
|---|---|---|
| `notary.name` | ФИО нотариуса | останется «Фамилия Имя Отчество» на всех страницах |
| `notary.address`, `addressParts` | адрес конторы | останется «ул. Примерная, 1» |
| `notary.geo` | координаты офиса | карта покажет чужое место |
| `notary.phone`, `phoneHref`, `phoneE164` | телефон в трёх видах | останется «+7 (999) 999-99-99» |
| `notary.email` | почта | останется `info@notarius.ru` |
| `notary.practiceSince` | год начала практики, например `'2010'` | счётчик стажа не показывается |
| `notary.license`, `registryNumber` | лицензия и реестровый номер | строки не показываются |
| `notary.workingHours`, `openingHoursSpec` | часы приёма | будет стандартное пн–пт 10–19 |
| `notary.telegram`, `vk` | соцсети | ссылки ведут в никуда |
| `siteUrl` | **домен сайта** | адрес возьмётся из имени сборки и устареет при следующем деплое |
| `yandexOrgId` | номер организации в Яндекс.Картах | вместо отзывов Яндекса — заглушка |
| `photos.portrait` | путь к портрету, например `'/notary.jpg'` | вместо фото — буква фамилии |
| `photos.office` | снимки конторы | блок со снимками не выводится |
| `documentsDone` | сколько документов оформлено | счётчик не показывается |

`siteUrl` — единственное поле, из-за которого сайт нельзя просто оставить
как есть: от него зависят canonical, sitemap и разметка. Пока домена нет,
подойдёт адрес проекта на Vercel.

### 2. `lib/prices.ts` — цены

**Единственное место, где правятся цены.** Оттуда же берёт числа калькулятор
на главной, поэтому таблица и калькулятор разойтись не могут.

Первая колонка — нотариальный тариф, он установлен Налоговым кодексом
и одинаков у всех; трогать не нужно. Вторая и третья — УПТХ и итог, они
у каждого нотариуса свои: их и правят.

Услуга попадает в калькулятор, если у строки заполнено поле `calc`.

### 3. `lib/reviews.ts` — отзывы

**Заполнено образцами — заменить обязательно.** Неподставленный телефон
бросается в глаза сразу, а отзыв выглядит настоящим и может уехать в боевой
сайт незамеченным; отвечать за него будет нотариус.

Пустой список — тоже рабочий вариант: блок отзывов тогда не выводится.

### 4. `lib/services.ts`, `lib/checklists.ts` — услуги и что взять с собой

Перечень услуг и списки документов к ним. Разумны по умолчанию, но стоит
свериться: контора может не вести какие-то направления.

### 5. `lib/faq.ts` — частые вопросы

Ответы у каждого свои: где-то принимают без записи, где-то работают
по субботам.

### 6. `lib/articles.ts` — блог

Пять статей общего характера. Можно оставить как есть — они не про
конкретную контору.

## Проверить перед запуском

- [ ] `siteUrl` — настоящий домен, а не адрес сборки
- [ ] отзывы заменены на настоящие или список очищен
- [ ] телефон, адрес и ФИО не остались заглушками
- [ ] цены сверены с нотариусом
- [ ] фотографии положены в `public/` и прописаны в `photos`

Быстрая проверка, что заглушек не осталось:

```bash
grep -rn "Примерная\|999-99-99\|Фамилия Имя\|info@notarius.ru" lib/
```

## Запуск

```bash
npm install
npm run dev
```

## Варианты оформления

Один и тот же сайт в четырёх видах — по ветке на каждый:

| Ветка | Вид |
|---|---|
| `template` | тёмно-синий с золотом, единственный с виджетом приёма заявок |
| `site-lavender` | лавандовый, с калькулятором стоимости |
| `site-warm` | тёплый терракотовый, с чек-листом «что взять» |
| `site-modern` | зелёный, с поиском ближайшего свободного времени |

У трёх вариантов оформления своя запись на приём с базой (Prisma) и свои
страницы `/admin` и `/staff`. У `template` записи нет — вместо неё виджет
внешнего сервиса заявок.
